UDJ — Card & button press interactions

Replaces the default grey tap-flash with one coherent press system across the app. Three tiers built from a single spring, so every tap feels like it belongs to the same product.

Target · React Native (Expo) Engine · Reanimated 3 + Pressable For · Claude Code v · 2.0 · single-node

0 · First, remove the current behaviour

The grey box on press is the platform default — it comes from TouchableHighlight (its underlayColor) or the Android TouchableOpacity/Pressable ripple. Before adding the new system:

  • Replace every TouchableHighlight / TouchableOpacity on these surfaces with the <Pressable>-based component below.
  • On Android, explicitly pass android_ripple={null} so no ripple is drawn.
  • Globally keep <Pressable>'s default — it has no highlight unless you add one. Our feedback comes entirely from the animation, not from a background flash.

2 · Motion tokens

One press-in curve, one release spring, shared by every scale-based tier. The slight overshoot on release is what makes it feel alive rather than mechanical.

TokenValueUsed for
PRESS_INwithTiming, 110ms, Easing.out(Easing.quad)Finger down — fast, no bounce
RELEASEwithSpring · damping 15 · stiffness 200 · mass 0.7Finger up — gentle overshoot back to rest
TINT_FADEwithTiming · in 70ms / out 240msOverlay-only tiers (tint) — no spring

Ink colour for overlays / shadows is the app's near-black #21302A (token ink). Card base shadow stays as today: shadowOpacity 0.07, radius 10 (iOS) / elevation 3 (Android).

Wash colour is a theme token, not a constant

The press wash must come from a theme-aware token, not a hardcoded value — a black wash is invisible on dark surfaces, exactly where feedback matters most. Define pressWash per theme:

TokenLight modeDark modeNotes
pressWash#21302A (near-black)#FFFFFF (white)The overlay colour; opacity comes from the tier preset.

Why this can't be hardcoded

The 4–6% black wash is tuned for light/white surfaces. On a dark surface, black-on-dark is near-invisible. On a saturated surface (the jade GPA hero) black reads as “muddy,” not “pressed” — which is the reason the GPA hero is a settle tier (overlay 0, scale-driven), so it never relies on the wash. Build pressWash as a token now: it's a one-line addition pre-migration, but a find-replace-and-retest if bolted on after dark mode lands.

3 · The reusable component

One component, one node, all five behaviours via a tier prop. Drop it in components/PressBox.tsx. The single node is built with Animated.createAnimatedComponent(Pressable) so the caller's full style lands directly on the node the parent measures — this is what prevents the flex-collapse (see §7). The wash overlay is an absoluteFill child that clips itself via its own borderRadius, so we never set overflow:'hidden' and iOS shadows render on every tier. Its colour comes from the pressWash theme token (§2) — never a hardcoded ink.

// components/PressBox.tsx
import React from 'react';
import { Pressable, Platform, StyleSheet, PressableProps, ViewStyle } from 'react-native';
import Animated, {
  useSharedValue, useAnimatedStyle, withSpring, withTiming, Easing, interpolate,
} from 'react-native-reanimated';

// Create ONCE at module scope — never inside the component (re-creates type every render).
const AnimatedPressable = Animated.createAnimatedComponent(Pressable);

const RELEASE = { damping: 15, stiffness: 200, mass: 0.7 };
const PRESS_IN = { duration: 110, easing: Easing.out(Easing.quad) };

type Tier = 'lift' | 'settle' | 'button' | 'icon' | 'tint';

const PRESET = {
  lift:   { scale: 1.02,  overlay: 0,    shadow: 'up'   },
  settle: { scale: 0.98,  overlay: 0,    shadow: 'down' },
  button: { scale: 0.965, overlay: 0.06, shadow: 'down' },
  icon:   { scale: 0.90,  overlay: 0.06, shadow: 'none' },
  tint:   { scale: 1.0,   overlay: 0.04, shadow: 'none' },
} as const;

type Props = PressableProps & {
  tier?: Tier;
  style?: ViewStyle;        // full surface style — layout AND visual, all on the one node
  radius?: number;          // corner radius for the wash overlay; defaults to style.borderRadius
  children?: React.ReactNode;
};

export function PressBox({ tier = 'lift', style, radius, children, disabled, ...rest }: Props) {
  const cfg = PRESET[tier];
  const { pressWash } = useTheme();   // near-black in light, white in dark — NEVER hardcode
  const p = useSharedValue(0);
  const isTint = cfg.scale === 1 && cfg.shadow === 'none';
  const r = radius ?? (StyleSheet.flatten(style)?.borderRadius as number) ?? 0;

  const node = useAnimatedStyle(() => {
    const out: any = { transform: [{ scale: interpolate(p.value, [0, 1], [1, cfg.scale]) }] };
    if (Platform.OS === 'ios' && cfg.shadow !== 'none') {
      const hiOp = cfg.shadow === 'up' ? 0.16 : 0.05;
      const hiR  = cfg.shadow === 'up' ? 22   : 4;
      // shadowOffset stays static; only opacity + radius animate.
      out.shadowOpacity = interpolate(p.value, [0, 1], [0.07, hiOp]);
      out.shadowRadius  = interpolate(p.value, [0, 1], [10, hiR]);
    }
    return out;
  });

  const wash = useAnimatedStyle(() => ({ opacity: interpolate(p.value, [0, 1], [0, cfg.overlay]) }));

  return (
    <AnimatedPressable
      disabled={disabled}
      android_ripple={null}
      onPressIn={() => { if (disabled) return; p.value = isTint ? withTiming(1, { duration: 70 }) : withTiming(1, PRESS_IN); }}
      onPressOut={() => { if (disabled) return; p.value = isTint ? withTiming(0, { duration: 240 }) : withSpring(0, RELEASE); }}
      style={[style, node]}        // full style + animation on the SAME node the parent measures
      {...rest}>
      {children}
      {cfg.overlay > 0 && (
        <Animated.View pointerEvents="none"
          style={[StyleSheet.absoluteFill, { backgroundColor: pressWash, borderRadius: r }, wash]} />
      )}
    </AnimatedPressable>
  );
}

The rules that keep this working

1 · Never set overflow:'hidden' on the node — the wash clips itself via its own borderRadius, so shadows survive on every tier (incl. button). 2 · AnimatedPressable is created once at module scope; defining it in the body re-creates the type each render and breaks the animation. 3 · Don't use Pressable's function style/children — animation is driven by the shared value, so the component never needs to re-render on press. 4 · Android can't smoothly animate elevation; keep it static on the card style and let scale carry the effect there. 5 · The wash colour is the pressWash theme token — never a hardcoded ink, or feedback disappears in dark mode.

6 · Accessibility & polish

  • Dark mode wash. The press wash uses the pressWash theme token (§2): near-black in light mode, white (~8–10%) in dark mode. A black wash on a dark surface is invisible — never hardcode the colour. Wire this token from the start, even though dark mode ships later.
  • Reduce Motion. If AccessibilityInfo.isReduceMotionEnabled() is true, skip the scale on all tiers and fall back to the tint behaviour (wash via pressWash) so there's still feedback without movement. Read it once at mount and gate the onPressIn/Out bodies on it.
  • Scroll cancellation. Pressable inside a ScrollView/FlatList already cancels the press when a scroll begins, so the card won't stick in its pressed state — no extra work needed.
  • Haptics (optional, recommended for Tier 1). On onPressIn for lift + settle cards, fire Haptics.selectionAsync() (expo-haptics). Skip it for tint rows and nav tabs to avoid buzz spam.
  • Hit slop. Keep the existing hitSlop on the small icon buttons; the 0.90 scale must not shrink the touch target below 44pt.
  • Disabled state. When disabled, pass it through to Pressable and short-circuit the animations (no scale, no wash).

Acceptance check

Press & hold any schedule card → it grows ~2% and the shadow deepens, springs back on release, no grey box. Feature card & grade hero shrink ~2% instead. Buttons press in with a faint darken. Rows show only a soft wash. All share the same release bounce. Reference feel: the UDJ — Press System Demo prototype.

7 · Why single-node (post-mortem)

The first implementation (v1.0) wrapped <Pressable> around an inner <Animated.View style={fullStyle}> — two nodes. This collapsed every flex-sized surface and is the reason we reverted. Recording it so we don't repeat it.

  • Root cause. In React Native flex layout the parent measures the outer node — here the unstyled Pressable. All the sizing (flex:1, alignSelf:'stretch', aspectRatio, width-by-stretch) lived on the inner view the parent never sizes. The Pressable shrank to content/zero, and the added overflow:'hidden' clipped the content to an empty rounded box.
  • Why it looked selective. Surfaces sized by their parent collapsed — stat-card row, semester segmented control, day cells, tab-bar cells, profile/student card. Full-width cards with intrinsic content height — schedule, news, agenda, grade hero — don't depend on parent flex sizing, so they survived. That split is the signature of this bug.
  • The half-fix we rejected. Splitting style keys (layout → Pressable, visual → inner view) works in theory but has too many edge cases (margin vs padding, transforms, percentage sizing, shadow-vs-clip), so it stays brittle.
  • The fix (v2.0). Collapse to one node via Animated.createAnimatedComponent(Pressable). The caller's full style sits on the exact node the parent measures, so flex/stretch/aspect-ratio all resolve normally. Bonus: scale is a post-layout transform, so a pressed card never reflows its neighbours.
  • The clip trap, avoided. v1.0 clipped the wash with overflow:'hidden' on the card node — which on iOS also clips the card's own shadow, and breaks the button tier (shadow + wash together). v2.0 gives the wash its own borderRadius and never sets overflow:'hidden', so shadow and wash coexist on one node.

If a surface still collapses after this change

It means a layout style isn't reaching the node — check the caller is passing flex/width on the style prop given to PressBox (not on a wrapping <View> that's now redundant). There should be no intermediate view between the parent and PressBox holding the sizing.
