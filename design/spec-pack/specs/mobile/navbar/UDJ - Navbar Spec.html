UDJ — Bottom Navigation Spec

Implementation reference for the app-wide floating bottom navigation — a rounded pill that hovers above the content with five destinations: Accueil · Agenda · Notes · Actus · Profil. Icon-only, with a filled jade pill + dot marking the active tab. This spec covers layout, the exact icon assets, colour tokens (light/dark), RTL, and — critically — how it sits above the device's system navigation (the on-screen back / home / recents buttons or the gesture pill) so it never collides with them. Wire the values as tokens; don't hardcode.

1 Layout tree

NavBar // position:absolute · left/right 14 · bottom 14 + insets.bottom └─ Bar height 60 · radius 22 · surface · navShadow · (dark: +1px hair border) └─ 5× Cell flex:1 · centers its pill · full-height tap target └─ Pill 46×46 · radius 15 · bg jade when active, else transparent ├─ Icon ~22px optical · #fff when active, text2 when inactive └─ Dot 4px · white@90% when active · invisible spacer otherwise

Order: home · schedule · grades · news · profile (Accueil · Agenda · Notes · Actus · Profil). In RTL (Arabic) the array is reversed and the bar gets direction:rtl, so Accueil sits on the right. The whole bar is one row of equal flex:1 cells; the tap target is the full cell (≈60px tall), not just the 46px pill — comfortably above the 44px minimum.

3 Icons — exact assets

Five SVGs from the design file. Their raw exports have tight, inconsistent crops (16×18, 18×12, 20×20, 21×21, 24×24), so rendering them at a shared size still looks unbalanced — each glyph fills its own box by a different amount. The fix: each icon is re-framed into one shared 24×24 viewBox, glyph centered and optically scaled (heavier filled icons slightly smaller, lighter stroke icons slightly larger) so all five carry equal visual weight. Then render every icon at the same uniform size — no per-icon width/height, no wrapper boxes. Ship the normalized files in nav-icons/.

Each normalized SVG already paints with currentColor (fill for home/schedule/grades, stroke for news/profile) inside a <g transform> that does the centering + optical scale — so you just render it at a fixed size and drive one colour prop: active = #fff, inactive = text2. Stroke icons keep a visual ~1.5 (profile's raw stroke is pre-compensated to 1.714 because its group is scaled 0.875). Do not wrap these in extra padding boxes or re-derive per-icon sizes — the normalization already balances them.

5 System navigation & safe area — the important bit

The rule

The floating bar must sit ABOVE the system navigation, on every device.

Phones differ at the bottom edge: some use a thin gesture pill, others a 3-button bar (back / home / recents), and iPhones have a home indicator. Never hardcode bottom: 14 — that overlaps the buttons on a 3-button phone. Offset by the device's bottom safe-area inset so the bar always clears whatever is down there.

bottom = baseGap (14) + safeAreaInsets.bottom

↑ On a 3-button phone the bar floats clear above back / home / recents — because bottom = 14 + insets.bottom.

Implementation (React Native + Expo)

// use react-native-safe-area-context (already standard in Expo)
import { useSafeAreaInsets } from 'react-native-safe-area-context';

const insets = useSafeAreaInsets();
const GAP = 14;

// the floating bar
<View style={{
  position: 'absolute', left: GAP, right: GAP,
  bottom: GAP + insets.bottom,   // ← clears gesture pill OR 3-button bar OR home indicator
  height: 60, borderRadius: 22,
}} />

// every scroll screen must reserve room so content isn't hidden behind it
<ScrollView contentContainerStyle={{
  paddingBottom: GAP + 60 + GAP + insets.bottom,  // gap + barHeight + gap + inset
}} />

Notes. (1) insets.bottom only reports a non-zero value when the app draws edge-to-edge under the system bars — which is the default on modern Expo/Android 15. If edge-to-edge is off, the OS reserves the nav-bar space itself and insets.bottom is 0; the GAP-only fallback above is correct there too. (2) Wrap the app in <SafeAreaProvider> once at the root. (3) Don't use SafeAreaView with edges to pad the bar — read the raw inset and add it to bottom, so the bar keeps floating (a padded SafeAreaView would push a flush look). (4) Re-read insets on rotation / foldables — the hook updates automatically.

6 If you ever switch to a flush bar

The reference design also has a flush, edge-to-edge bar with text labels (Home · Agenda · Notes · Actus · Profile). If you adopt that instead of the floating pill, the safe-area rule changes shape: don't offset bottom — instead add insets.bottom as padding inside the bar so the row of icons stays above the system buttons while the bar's background still bleeds to the screen edge.

<View style={{
  position: 'absolute', left: 0, right: 0, bottom: 0,
  height: 64 + insets.bottom,
  paddingBottom: insets.bottom,   // ← icons lift above the buttons; bg fills to the edge
  backgroundColor: surface,
}} />

Either way the principle is the same: the touchable icons must never enter the insets.bottom band. The floating pill (§1–5) is the shipped direction; this is only for reference.

7 Interaction & states

  • Tap a cell → onTab(id); the active id drives the jade pill + dot + white icon. One tab is always active.
  • No labels — icon + dot only (the floating pill stays compact). Labels live in the flush variant (§6).
  • Active marker = filled jade pill behind the icon and the 4px dot beneath it; inactive cells render a 4×4 transparent spacer so every icon shares the same vertical centre.
  • Persistent across all five primary tabs; it is not shown on pushed/detail screens or pre-auth (login).
  • RTL reverses tab order and sets direction:rtl.
  • Hit target is the full cell (~60px tall × one-fifth width), well past the 44px minimum.
