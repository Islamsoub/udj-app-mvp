1 · Attendance bands, relative to the server threshold

Decision. The server computes the band and the client only maps it to a colour. That is the only way phone and web cannot disagree. Neither client hard-codes a percentage.

Inputs

NameSourceDefaultMeaning
Tsettings.attendanceThreshold75Minimum rate, in %
Msettings.attendanceWarnMargin (new)10Points above T that still count as "near"
Wsettings.attendanceWarnAbsences (new)2Absences left at or below which a subject counts as "near"
heldH, attendedHper subject, from actual session records to date—Same records and counting rule as the rate (justified absences per existing policy)
remainingHper subject, sessions still scheduled in the timetable from now to semester end (cancelled excluded)—Recomputed on every timetable change; reaches 0 at term end
rate = attendedH / heldH × 100 // displayed figure, to date bestCase = (attendedH + remainingH) / (heldH + remainingH) × 100 hoursLeft = attendedH + remainingH − T/100 × (heldH + remainingH) absencesLeft = max(0, floor(hoursLeft / sessionLength)) // shown in sessions band = "below" if bestCase < T // perfect attendance from here can no longer reach T "near" if rate < T + M or absencesLeft ≤ W "ok" otherwise
Decision: option 2, recoverability against what remains scheduled. No stored total. The rate and the allowance share one hour universe: past hours come from session records and future hours from the remaining timetable. Curriculum hours (hoursCm/Td/Tp) are not used. Holidays and exam weeks may inflate remainingH early in term, which errs generous. The error shrinks every week and is zero at term end, where bestCase equals the final rate. A student at 3/3 is green, and an early 1-of-2 miss is amber, not red, while it can still be recovered.

hoursLeft answers "how many more hours can be missed and still finish at T". bestCase < T is the same test as hoursLeft < 0. sessionLength is the subject's standard session duration. The overall figure pools all four inputs across subjects. If heldH = 0, show "—" and band "ok". If remainingH = 0, the result reduces to rate < T. If the university changes T, every boundary moves with it.

Per subject or overall?

Both, with clear jobs. Formal warnings are per subject, as the notification shows. The ring shows the overall rate and is coloured by the overall band, so the colour always describes the number next to it. The sentence under "Seuil" reports the most at-risk subject.

Empty week

The button stays enabled. The sheet prints the full header and an empty grid, with a centred boxed message: "Aucun cours cette semaine" / "Aucun cours n'est programmé du {from} au {to}." This gives the student proof of an empty week rather than a blank page.

Arabic

Yes, the sheet mirrors. dir="rtl" on the sheet: Monday is at the right, the hour gutter is on the right, the rail sits on the right edge (border-inline-start), and the brand is at the right with the ID block at the left. Day names are written in full (الاثنين …) in Noto Naskh Arabic. Times, codes, the student number and room codes stay LTR (.mono / <bdi>). Course titles use the backend's Arabic name, falling back to French inside <bdi>.

Implementation

  • Render the sheet into a .print-root appended to body. Add @media print{body>*:not(.print-root){display:none}}, wait for document.fonts.ready, call window.print(), then remove the root on afterprint.
  • The print stylesheet is the delimited block in schedule-print.html. Copy it as-is.

3 · Tagline contrast, measured on the gradient

Geometry used: login card 420 px wide, hero 195 px tall (40 + 64 logo + 14 + 25 title + 5 + 17 tagline + 30), linear-gradient(155deg, #1D9E75, #0F6E56). The tagline line box spans y 148–165 px and is about 242 px wide, centred.

At 100% white, the current layout passes by 0.01. That is too thin to rely on: the Arabic string is wider, the card shrinks on phones and the font metrics vary.

Decision: darken the gradient start, not a position rule. New hero gradient: linear-gradient(155deg, #168666, #0F6E56). #168666 alone gives 4.53 : 1 with white, so every point of the hero passes 4.5 : 1, in any layout, language or width. Use it in both themes, and on the dashboard GPA card (150deg) too.

Confirmed: change the server template. The card and the notification must point at the same subject, and that is not possible without the subject in the text.

  • {subject}: the subject's name in the recipient's locale, falling back to French. The client wraps it in <bdi>.
  • {rate}: an integer, truncated, not rounded. 74.6 must show 74, never "75 %, sous le seuil de 75 %".
  • {threshold}: settings.attendanceThreshold at send time.
  • FR uses U+202F (narrow no-break space) before %. AR uses Western digits and ٪ (U+066A), consistent with the rest of the app.
  • When to send: only on band transitions, computed with the rule in §1. Send near on entering near and below on entering below, each once per subject per semester. No notification on the way back up.
