1. How to read this document

This spec assumes the visual design system (colors, type, spacing tokens) is already defined and built in the reference prototype. It focuses on what a static screenshot can't show: what moves, what responds to a click or hover, and how the app behaves as a PWA — install, offline, session, and sync. Every section below is implementation-ready: durations, easings, and triggers are specified in CSS-equivalent terms so engineering can drop them in directly.

2. Motion tokens

Four durations and two easings cover every animation in the product. Do not introduce new values — reuse these.

TokenValueUse for
--dur-instant100msButton press, checkbox/toggle flip, icon color change
--dur-fast180msHover states, dropdown open/close, tab underline slide
--dur-base250msPanel slide-in, modal fade, toast enter, view transitions
--dur-slow450msSkeleton shimmer sweep, gauge/ring fill on load, theme crossfade
--ease-outcubic-bezier(.16,1,.3,1)Anything entering the screen (panels, toasts, dropdowns)
--ease-in-outcubic-bezier(.4,0,.2,1)Anything resizing in place (sidebar collapse, accordion, tab switch)

Respect prefers-reduced-motion: reduce globally: collapse every transform/opacity transition to --dur-instant with no easing curve, and disable the skeleton shimmer sweep (show a static tone instead).

3. Global interaction rules (web-specific)

Hover

Every clickable element gets a hover state — this is new relative to the mobile app. Buttons/links darken 1 step (jade → jade-hover) or gain a tinted background (jade-faint) over --dur-fast. Cards that are clickable (quick links, article cards, course blocks) lift 1px on translateY(-1px) and increase shadow to --shadow-lg over --dur-fast.

Focus (keyboard)

Every interactive element shows a 2px jade outline with 2px offset on :focus-visible only (never on mouse click). Focus order follows visual/DOM order: sidebar nav → topbar (bell, avatar) → page content → bottom actions. Modals/panels trap focus and return it to the trigger element on close.

Cursor

pointer on anything clickable (buttons, cards with a click handler, table headers that sort, chips, tabs). default on static text/content. text on editable note fields. not-allowed on disabled buttons (also drop opacity to 0.5).

Press feedback

On :active, buttons scale to 0.97 over --dur-instant with no easing delay — this is the only place a "press" is simulated (no ripple effect; that's a native-Android pattern, not used here).

4. Page & view transitions

Sidebar navigation
Clicking a nav item swaps the active view instantly (no crossfade) but the page title in the topbar crossfades over --dur-fast, and a 2px jade progress bar sweeps left→right along the top edge of the content area over --dur-base to signal a "page load" even though data is already cached client-side. The clicked nav item's background tints to jade-faint over --dur-fast; the previously active item un-tints over the same duration, running in parallel.
Initial dashboard load
Cards fade+rise in a staggered sequence: each card animates opacity 0→1, translateY(8px→0) over --dur-base with --ease-out, staggered 40ms apart in reading order (schedule → GPA → attendance → notifications → quick links → news). Runs once per session on first dashboard visit only, not on every nav click back to it.
Route change on mobile
Bottom-tab switches use the same instant-swap + progress-bar pattern as desktop sidebar nav — no slide transition between tabs (slide is reserved for drill-down navigation, e.g. opening an article or course detail, not lateral tab switches).

Inputs & forms

  • Focus: border color → jade, 3px jade-faint glow ring appears via box-shadow, over --dur-fast.
  • Error: border → danger, background tints danger-bg; an inline error message slides down (max-height 0→auto + fade) beneath the field over --dur-fast.
  • Password field toggle: eye icon click crossfades the input between type=password and type=text masking — no layout shift.
  • File drop zone (justification upload): dragover state adds a jade dashed border + jade-faint background over --dur-instant; drop triggers the upload-progress bar animating 0→100% in discrete steps (matches the current prototype's simulated 20%-per-tick fill), then crossfades to a doc-chip confirmation.

Tabs / segmented controls

The active pill background slides between options rather than the whole control repainting: implement as one absolutely-positioned pill element that animates its transform: translateX() and width to the clicked button's bounding box over --dur-fast with --ease-in-out. Text color crossfades in place, not on a delay.

Data tables (Grades, Attendance)

  • Sort click: the clicked column header's sort caret rotates 180° over --dur-fast; rows re-order by having each <tr> animate its vertical position with a FLIP transition (record old position, animate transform: translateY() from old→0) over --dur-base — avoids a jarring re-render.
  • Row hover: background tints surface2 instantly (--dur-instant), no delay — tables are scanned quickly and should feel responsive.
  • Status pill color: never animates on its own; it only changes when underlying data changes (e.g. a grade is published), in which case it fades in from 0 opacity over --dur-base to draw the eye.

Cards & hero stats

  • GPA / Attendance ring or gauge fill: animates from 0% to its target value once, on first paint of that view, over --dur-slow with --ease-in-out. Re-visiting the same view in the same session does not replay it (avoid feeling gimmicky on repeat).
  • Sparkline draw-in: the GPA history polyline animates via stroke-dasharray/stroke-dashoffset from fully hidden to fully drawn over --dur-slow, same first-paint-only rule as above.
  • Clickable stat cards (Assiduité, À la une) lift + shadow on hover per the global card rule in §3.

Dropdowns & popovers (notification bell, avatar menu)

Enter: opacity 0→1 + translateY(-4px)→0 + scale(.97)→1, over --dur-fast, --ease-out, transform-origin top-right (top-left in RTL). Exit: reverse over --dur-instant, no easing. Closes on: click outside, Escape, or selecting an item. Only one popover open at a time — opening one closes any other.

Toasts

Enter from the bottom: opacity 0→1, translateY(8px→0), over --dur-fast --ease-out. Auto-dismiss after 2200ms by reversing the same transition. Stack new toasts above existing ones with 8px gap; if 3+ are queued, older ones dismiss early (max 2 visible). Never blocks input — toasts are non-modal and sit above content but below modal panels.

Slide-in detail panels (course detail, calculator, justification)

Desktop/tablet: panel slides in from the inline-end edge — translateX(100%)→0 (mirrored to -100%→0 in RTL) over --dur-base --ease-out; a scrim fades in 0→0.4 opacity in parallel. Mobile (<640px): the same panel becomes a bottom sheet — translateY(100%)→0 over the same duration, with rounded top corners. Close on: scrim click, Escape, the ✕ button, or (mobile only) a downward drag past 40% of the sheet's height. Closing reverses the entrance transition.

Skeleton loading state

Skeleton blocks (gray rounded rectangles matching each real element's footprint) use a shimmer: a lighter diagonal band sweeps left→right across every skeleton block in parallel, looping every --dur-slow×2 (900ms), via a moving background-position on a linear gradient. Skeletons never show for less than 400ms even if data resolves instantly (prevents flicker) and crossfade into real content over --dur-fast.

6. Theme, language & direction switching

Light ↔ Dark
All color-token-driven properties (background, text, borders) crossfade over --dur-slow by transitioning background-color, color, and border-color globally (a single CSS rule on * scoped to these three properties, removed immediately after the transition ends to avoid interfering with hover/focus timing). Icons that are theme-dependent (none currently) would crossfade in place.
FR ↔ AR (RTL flip)
Setting dir="rtl" is instant (no animated mirroring — physical properties like inset-inline-start already handle layout mirroring via CSS logical properties, so nothing needs to visually "flip" on a timer). The one exception: the sidebar/panel slide directions (see §5) must read the current dir at animation time, not assume LTR.
Font swap
Switching to Arabic swaps the body font stack to Noto Naskh Arabic; this is a discrete swap, not animated (animating font-family causes reflow jank). Numbers/times stay in the Latin/mono font in both directions per the inherited design system rule.

7. Sidebar collapse & responsive behavior

  • Manual collapse (desktop): clicking "Réduire" animates sidebar width: 240px→72px over --dur-base --ease-in-out; labels fade out over the first half of the transition (--dur-fast) so they don't wrap/clip mid-animation, then display:none. Content area reflows to fill the reclaimed width in the same transition (no separate delay). The chevron icon rotates 180° in sync.
  • Auto tablet collapse (640–1024px): same visual end-state as manual collapse, but driven by a resize observer, not a click — animates the same way if the resize crosses the breakpoint while the tab is open (rare), otherwise it's simply the initial state.
  • Mobile (<640px): sidebar unmounts (not just hidden) in favor of the bottom tab bar; switching between them is a hard breakpoint change, not an animated transition, since it corresponds to a full input-model change (touch-first vs cursor-first).

8. PWA-specific behaviors

Install prompt

A dismissible banner appears at the very top of the viewport (above the topbar, full-width, jade-faint background) on first visit, only when the browser fires beforeinstallprompt. Copy: "Installer Unipocket pour un accès plus rapide" with a primary "Installer" button and a text "Plus tard" dismiss. Enters via height: 0→auto + fade over --dur-base, pushing content down (not overlaying it). Dismissing stores a timestamp in localStorage; suppress re-showing for 30 days. On successful install, show a one-time full-screen splash (logo centered, jade-faint background, ~600ms) immediately after the installed app's next launch, then crossfade to the login/dashboard.

Offline behavior

Losing connectivity: a persistent banner slides down from under the topbar — "Vous êtes hors ligne. Données mises en cache affichées." — over --dur-base, warning-tinted. Every screen that has cached data keeps rendering it normally; a small mono timestamp ("Dernière synchronisation : …") appears near the page title to disclose staleness. Screens/actions that require a live connection (submitting a justification, changing password) show their primary action button disabled with the label replaced by "Connexion requise" — no destructive hiding of the form, just a blocked submit. On reconnect: the offline banner slides back up over --dur-fast, a toast confirms "Connexion rétablie", and any queued actions (e.g. a note edit made offline) auto-retry silently; only show a toast for the retry if it fails.

Session expiry

On a 401 from the API (access token + refresh both invalid), a modal overlay appears — center-screen on desktop, full-width bottom-sheet-style on mobile — fading/rising in like any other modal (§5). Copy: "Votre session a expiré" with two actions: "Se reconnecter" (primary, routes to login) and "Continuer hors ligne" (secondary, dismisses the modal and lets the user keep browsing cached data read-only). This modal cannot be dismissed by clicking outside or Escape — it requires an explicit choice, since silently losing it could confuse an already-confused, logged-out user.

Background sync indicator

When the service worker performs a background revalidation (stale-while-revalidate), do not show a spinner or skeleton — the screen already has cached content on display. Instead, briefly pulse the "last synced" timestamp label (opacity 0.5→1, --dur-base) when the data actually changes underneath the user, without disrupting scroll position or focus.

9. Screen-by-screen interaction notes

Login

Submitting animates the button into its loading state (§5) immediately; on error, the button reverts and the error card slides down above the fields (max-height technique, --dur-fast) while both fields' borders flash to danger red. The account-locked countdown (5 min) renders as a live mono timer inside the disabled submit button, re-enabling it automatically at 0:00 with a brief button pulse to signal it's active again.

Dashboard

The countdown-to-next-class pill live-updates every 60s without any transition (a static text swap — animating a ticking timer draws unwanted attention). Notification bell badge count animates in with a small scale(0)→1 "pop" (--dur-fast, slight overshoot easing cubic-bezier(.34,1.56,.64,1)) whenever a new unread notification arrives while the tab is open.

Schedule

Day/Week toggle uses the sliding-pill segmented pattern (§5). Week navigation (prev/next arrows) crossfades the week grid's course blocks out and back in over --dur-fast — content changes, the grid structure doesn't animate position. Clicking a course block opens the detail panel per §5; saving a note shows the button success-flash (§5) before the panel auto-closes after 500ms.

Grades

Semester tab switch fades the GPA hero's number via a quick crossfade (old value fades out 100ms, new fades in over the next 150ms — slight overlap avoids a "blank" flash) rather than sliding, since the two semesters aren't spatially related. The grade calculator panel's result updates live as the user types the target grade (debounced 150ms), with the result number using the same crossfade technique.

Attendance

The presence ring fill-on-load animation (§5) is the hero moment of this screen. Filtering absences (À justifier / Tout) crossfades the list rather than re-animating each row in — this is a filter, not new data. Opening the justification panel routes to one of four sub-states (upload form / pending / approved / rejected) with no transition between them since they're mutually exclusive server states, not something a user toggles.

News

Bookmark toggle: the bookmark icon fill animates via a quick scale(1→1.3→1) "bounce" over --dur-fast when saved, no animation when un-saving (removal should feel quieter than addition). Category filter chips use instant color swap, not a sliding pill (they're multi-select-adjacent in spirit, not a single-choice segmented control). Opening an article routes to the reader view with a forward-navigation feel: content slides in from the inline-end over --dur-base; "Retour" reverses it.

Profile

Toggle switches animate their thumb translateX over --dur-instant with a slight easing overshoot, matching native toggle feel. Theme/language radio-pills use the sliding-pill pattern (§5). "Vider le cache" shows a confirming toast and updates the last-sync timestamp with the pulse treatment from §8.

10. Accessibility notes

  • Focus order matches DOM/visual order throughout: skip-link → sidebar nav → topbar actions (bell, avatar) → page heading → primary content → any in-page secondary actions. Modals and panels trap focus and restore it to the triggering element on close.
  • ARIA roles: sidebar nav is a nav with aria-current="page" on the active item; tabs/segmented controls use role="tablist"/role="tab" with aria-selected; toasts announce via role="status" + aria-live="polite"; the session-expired modal uses role="alertdialog" with aria-modal="true".
  • Color contrast: all text/background pairs in both themes meet WCAG AA (4.5:1 body text, 3:1 large text/icons). Status colors (danger/warning/info/exam) are never the only signal — always paired with a label or icon.
  • Reduced motion: every animation in this document collapses per the rule in §2 when prefers-reduced-motion: reduce is set.
  • RTL: all layout uses CSS logical properties (inset-inline-start/end, margin-inline-*, border-inline-*) so mirroring in Arabic requires zero JS and zero duplicated CSS.
